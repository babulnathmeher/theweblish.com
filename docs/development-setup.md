## Repeat and security rules

- Indian mobiles are stored in `+91XXXXXXXXXX` form. One `Lead` is matched by normalized phone; each accepted submission adds a `SUBMISSION` activity in the same database transaction. A repeat updates latest contact and attribution fields without resetting status or assignment. Activity JSON preserves the submitted details.
- The endpoint accepts JSON of at most 8 KiB, requires same-origin `Origin`, exact landing path, consent, and an empty honeypot field. It limits each normalized phone to five attempts per 15 minutes through a MySQL counter keyed by HMAC. Set `TRUST_PROXY_IP_HEADER=true` only when a trusted reverse proxy overwrites `X-Real-IP`; then the same limit also applies per IP. This is a basic spam barrier, not a substitute for edge controls under a distributed attack.
- Preview expired `EnquiryRateLimit` rows with `npm run db:cleanup-rate-limits`. Run `npm run db:cleanup-rate-limits -- --apply` to remove only buckets older than 24 hours. Schedule that command on the selected host before sustained production traffic; no scheduler is configured yet.
- SMTP notification is optional. Configure all `SMTP_*`, `MAIL_FROM`, and `LEAD_NOTIFICATION_TO` variables to enable it. It runs after the database transaction; a delivery failure does not undo the lead.
- Better Auth owns credential hashing, session cookies, and its protected admin API. Public signup is disabled. Each admin page and every implemented lead action checks the session and `admin` role server-side before reading or writing data. Auth route matching accepts the canonical trailing slash generated by Next.js.

## Repeatable commands

Run `npm install`, `npm run db:validate`, `npm run db:generate`, `npm run db:migrate -- --name init` against a new development database, then set `ADMIN_SEED_EMAIL` and a unique strong `ADMIN_SEED_PASSWORD` in an ignored `.env` and run `npm run db:seed`. The seed refuses to overwrite an existing non-admin user and is idempotent for an existing admin. Run `npm run test`, `npm run test:db`, `npm run lint`, `npm run typecheck`, and `npm run build` to verify.

Do not commit `.env`. Rotate the local seed password after first use if this workspace is shared. The administrator bootstrap and database privileges need review before deployment.

## Blog, contact, and media additions

Migrations `20260929124002_blog_cover` and `20260929124906_contact_activity` were applied after `0001_initial` to the local development database. For a fresh development database, apply all checked-in migrations with `npm run db:deploy` before seeding. Published blog posts require `status=PUBLISHED` and `publishedAt` no later than now; the seven legacy slugs are reserved for audited import. The editor accepts a UTC publication time. Raw HTML in Markdown is not rendered.

The contact endpoint caps JSON at 8 KiB, checks the canonical contact page, consent, and honeypot, and uses email and optionally trusted IP rate buckets. A successful message is saved before any SMTP attempt. Configure `CONTACT_NOTIFICATION_TO` with the SMTP settings for optional email; development logs say when notification is skipped. Contact status and internal notes are recorded in `ContactActivity`.

Cover uploads require the server-only S3-compatible settings in [media-storage.md](media-storage.md). The upload action returns 503 to authenticated admins until storage is configured. No image bytes are saved in MySQL or the deployment filesystem.

The built HTTP smoke test runs with `npm run test:http` while the app is on `http://localhost:3217` and `BETTER_AUTH_URL` matches that origin. It uses the ignored local admin seed credentials, checks public/admin behavior, and removes its temporary post and contact record.
