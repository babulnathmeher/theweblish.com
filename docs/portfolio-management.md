# Portfolio case studies

The admin workspace at `/admin/portfolio/` manages client case studies. Administrators can search and filter projects, create a partial draft, attach an image from the existing media library, edit the brief, approach, and optional outcome, preview privately, publish, move back to draft, and delete with confirmation. Each page and server action calls `requireAdmin` before reading or changing portfolio data. The editor records the administrator and time of publication approval. Publishing requires a verified client name, substantive summary, challenge, approach, and an explicit confirmation that the client details and selected image may be shown.

Published, approved projects whose publication time has arrived appear on the existing canonical `/our-clients/` page. Drafts and unapproved records are excluded from the public query. Case studies use an anchor such as `/our-clients/#project-name`; there is no new detail route or redirect until the legacy route audit confirms one. The Our Clients page remains `noindex` and outside the sitemap while the route and content review remain incomplete. The optional SEO fields are stored for a future reviewed route. No project, result, client logo, or testimonial is seeded by this feature.

`prisma/migrations/20261012000000_portfolio_projects/` adds the `PortfolioProject` table without changing existing rows. On 2026-10-13 it was applied to the restored, isolated development database on port 3317 after a logical export and restore check. The original local MariaDB data directory on port 3306 was not migrated; its Aria and InnoDB issues still need review. The ignored local `.env` points to the isolated database. Start that server with `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-isolated-mariadb.ps1` and restart Next.js after a reboot. The admin list shows a migration notice if the table is unavailable. See [database-recovery.md](database-recovery.md) for the backup and restore record.
